# Independent review 3 — integration and Stage0 ports

## Findings

1. **P1 stored-source read trust regression.** `ai_tools.call` routes authoritative `_current` projections into `_model(spec)` without `trusted_projection=True` for gear_get_design and the rate/explain/sensitivity path. Importing the existing `MS.load_file()` source with `DS.commit_source` makes gear_get_design/gear_rate return blocked_invalid_inputs on its standard_constant inputs. An optimizer input is likewise rejected. Preview/commit trust fixes do not repair read consumers. Root assigned a separate narrow fix; pending recheck. Stateless/direct input must retain its protected-provenance rejection.
2. **P1 W2W original thermal-boundary regression.** The new W2W thermal calculation skips the original `p_in_w / 1000 * 1000` roundtrip through thermal_balance. Ordinary result differences are only ~2.8e-16 relative, but the boolean boundary changes: at `area_m2=1.669296396441226`, otherwise original flagship inputs, candidate index 9 is thermal_ok=True in the new port and False in the frozen solver. Registered evidence: w2w-boundary-probe.json. Preserve the original arithmetic path rather than adding a tolerance.
3. **P1 R3 lexical fail-closed still incomplete at this snapshot.** The four previous exact cases are repaired and NaN/Infinity are flagged. However common sign/magnitude forms still split into false sources: Unicode minus before 九百九十九 and Chinese 负 before Arabic 999 lose their signs; 1e3万 splits into 1000 and 10000; 1,000 splits into 1 and 0; 零万 becomes 10000. Root is replacing the scanner with whole-token handling. This concerns numeric lexical source identity, not semantic field accuracy. Do not extend a zero-traceability claim to semantic correctness.
4. **P2 strict API failure behavior.** `compile_requirement` with `family=[]` or `{}` raises TypeError before validation. Valid finite W2W values `k_w_m2k=area_m2=1e-300` underflow their product to zero and raise ZeroDivisionError outside the workflow catch. The MCP outer layer converts these to invalid-params RPC errors; it does not falsely accept them. Still, the direct workflow API should return its documented blocked result, and reject a zero/nonfinite derived denominator before use.

## Where This Review May Be Wrong

- The input boundary probes include finite extreme values; rejecting them is acceptable and preserving nonsensical legacy arithmetic is not required. The thermal pass/fail boundary probe uses ordinary finite engineering magnitudes and directly tests the unchanged original predicate.
- New source-read and scanner fixes are in progress concurrently; findings describe the inspected snapshot and need fresh rechecks before final disposition.
- This is source/oracle review, not external engineering validation. Candidate-level checks and declared Stage0 scope cannot establish family strength or full-system capability.
