# v0.17 FEA preparation

`gearmath.tools.fea_prepare.prepare(inp, solver_version='2.23')` derives element groups, deck surface rosters and strict output requests from the original M37 deck state parser. It checks these against the existing strict reader registry and records input, case, tool and bundled solver hashes. `verify(inp, manifest)` recomputes the declaration and refuses changed inputs or declarations. The actual solver binary hash identifies the bundled Linux executable; it does not establish execution. Revalidate against the actual binary before running.

The prepared evidence directory contains actual generator-produced L2 P01 d8/d12/d18, L3 center d8/d12/d18, and L3 ph10 d12 inputs and metadata, plus per-input manifests. The generator was run with gmsh 4.15.2, no solver; all manifests are blocked because the canonical reader has no CPE6 integration-point registration for CalculiX 2.23. The reader registers 2.23 CPE6 deck S3 to output face 5 from existing ph10 evidence; it does not register other faces. Exact missing mappings are reported by the strict validator. Element groups identify the candidate elements; no invented IP numbers are supplied. Contact output is active-row only and does not prove complete surface coverage. Whether CONTACT FILE is required remains undecided.

This is preparation, not a solved model, numerical FEA gate or acceptance result. No registry or ingestion verdict is changed. Case P01 is one subset of the L2 matrix; the full L2 sweep and remaining L3 variants are not generated here.

Independent follow-up: the bundled Linux CalculiX 2.23 binary ran the synthetic CPE6 L0 elastic patch under WSL. All 20 elements had stress and COORD keys 1–9 in its final `.dat`; input, `.dat`, `.sta`, solver hashes and reproducible checker are in `v017-system-run/fea-prepare/ip_probe.json` and `check_probe.py`. The binary hash agrees with `vendor/fea/vendor/FEA-RUNTIME-PROVENANCE.json`; upstream is https://www.dhondt.de/ccx_2.23.tar.bz2. Per-job manifests record this observed limited-scope mapping as a candidate alongside the element roster. The canonical strict reader itself does not yet register it, so manifests remain blocked for ingestion. The probe does not validate contact or a gear result. The existing reader records CPE6 S3→5 for 2.23 from ph10; no other 2.23 sides were proven by this patch.

Opt-in profile: `verified_profile(probe_dir, solver_path)` loads an isolated instance of the canonical reader only after SHA-256 checks of the exact solver and raw probe input, DAT and STA. Its only added entry is (`2.23`, `CPE6`) = 9; the canonical reader and its regression expectations are unchanged. `prepare(..., probe_dir=..., solver_path=...)` and `verify` use the same profile. Profile manifests for the eight selected decks report registration ready, meaning only that their declared field coverage is supported by this isolated profile. `contact_file_requirement` remains undecided, so formal L3 scope is not ready. Calling the isolated reader on the actual patch output accepted 180 stress and 180 coordinate keys; this does not constitute a gear FEA result. The original reader retains its earlier blocking behavior.
