01 / THE ARCHITECTURE CHOICE

主路线：数学单元插件 + 分层组合库 + 受控筛选。

采用你提出的方式：把常用传动配对方式封装成子元件，把常用多级组封装成复合子元件，预先搭建完整的声明范围内组合库。实际设计先从库选结构，再确定传动比分配、零件参数和工程约束。语言模型负责理解、查询、提议和解释；数值由数学系统产生。

方案A · 采用

有界库驱动

离线枚举和审阅结构，版本化维护；在线按要求筛选。易计数、易解释、易加入工业先例与失败记录，适合不超过4级的首版产品域。

方案B · 作为离线工具

语法自动生成

用相同单元和插接规则补全抽象组合、检查覆盖缺口。它用于更新库，不让未经审阅的新结构自动成为成熟方案。

方案C · 后续扩展

通用1D网络仿真

保留残差网络、能量端口和未来状态接口；首版先支持固定角色、单路径串联准静态编译。功率分流、离合换挡与动态DAE另立能力门。

本次明确的设计边界：不超过4个展开的齿轮传动级，少级数/少零件优先；首版不含分流、闭环功率路径、可切换离合与多挡状态组合。算法知道如何拒绝越界，不把“未支持”判为物理不可行。丝杆终端、齿轮级、啮合数和UI节点数分别记账。

“有限组合库”和“数学先行”可以同时成立：库内保存可编译的数学配方，不保存另一套手工计算结果。已求解的实例、制造/FE工件与工业案例作为配方的引用和证据，不能取代元件数学模型。

这五类库是业务对象划分，不是重命名现有软件L0～L7层级。工程先例可关联“家族”“有序结构”或“完整实例”，必须声明证据到底覆盖哪一层。

组合库不枚举所有尺寸

340表示家族序列数量。齿数、模数、螺旋角、材料、齿宽、行星数和布置姿态属于配方配置与具体实例。不能把无限或巨大参数空间提前展开成数百个“固定正确答案”。

库中结构也分成熟度

抽象插接合法 → 运动/能量可评估 → 详细工程可评估 → 有匹配的工业先例 → 完整实例已验证。目录默认从经审阅配方挑选；未审枚举条目留作补洞，不自动标成成熟方案。

03 / MATHEMATICAL CONTRACTS

子元件应是数学契约，不只是一个Python类。

一个单元必须说明：变量、端口、方程、边界、损耗/状态、适用域与校核能力。同一模型既能被单独计算，也能被系统编译器组合；外层只接线和提出约束，不另算齿轮关系。

类型化端口与连接

旋转功率共轭对：τ、ω；位置φ保留相位
平动功率共轭对：F、v；位置x
同一刚性连接（统一方向后）：φ₁=φ₂，τ₁+τ₂=0
平动连接：x₁=x₂，F₁+F₂=0

所有机械作用力/力矩统一取“进入元件为正”。公共轴线与参考方向先变换，再作连接。Modelica连接器以φ/x为potential，以τ/F为flow变量；ω/v是位置导数，术语不能与功率流图的速度流混淆。一手依据

能量约束与零速传扭

机械端口功率和 = 机械储能变化 + 损耗
输入功率 = 输出功率 + 损耗（准静态）
零速时仍需：运动约束 + 虚功/力矩约束

全端口记账不能只看总传动比；停机保持时功率均为零，单靠能量式无法决定力矩。需由约束Jacobian及静摩擦/边界模型确定可传扭域。热端口另接热平衡，不能把同一损耗重复扣除。

简单行星排保留第三端口

zₛ(ωₛ−ω꜀)+zᵣ(ωᵣ−ω꜀)=0
固定环：ωᵣ=0
太阳入、行星架出：i=1+zᵣ/zₛ
理想准静态：τₛ+τᵣ+τ꜀=0

固定环不是“无反力矩”；环的反力矩要进入箱体/安装口。只有明确固定构件、输入与输出角色后，才可对外缩约为两个动力端口。其他角色配置拥有不同语义ID与适用域。

蜗杆 / 丝杆的反向域

正驱损耗模型：L=f(速度、载荷、材料、润滑、温度…)
反驱：独立方法与适用域
自锁 / 静摩擦：边界与不等式，而非负效率

不能用正向η的倒数推导所有反向状态。数据缺失或静摩擦阈值未定时，返回具体blocked/underdetermined。丝杆终端连接旋转与平动端口，导程、旋向与支承随实例给出。

与现有量纲核衔接：当前内核把角度单列为A维，rpm规范化为转频而非角速度。拟新增端口ω[rad/s]时，按 P=τ·ω/(1 rad) 处理角度桥；转频到ω需2π rad/rev。通用角速度/惯量单位和转换需单独测试，不能偷偷忽略A维或把单位只写成字符串。

每个插件对外输出能力矩阵：运动学、正驱/反驱功率、啮合力、几何、强度/寿命、热、CAD、FE分别为supported / provisional / unsupported，并绑定方法、数据、域与证据。通过端口检查，只说明能连接；不意味着所有校核已通过。

快速过滤可以做什么

按库中明确的齿比区间、级数/元件类型、端口、受支持工况、空间关系约束和成熟度减少候选。没有来源的比值界、摩擦/效率或空间尺寸不可补成默认值；没有该模型时保留未知。

空间约束不能只用方向标签

H平行偏置、P同轴、B相交与W/X交错只是局部关系。两次转向或平行偏置可有多种位置；最终轴线是否同轴、总成是否装得下，必须由坐标/姿态与参数化布局求解，随后做几何与运动检查。

给用户的“多个方案”应优先体现不同架构，而不是一个家族的几十个齿数点。每个结构保留若干参数与裕量备选；总体排序同时展示少级数、零件/支承复杂度、能量损失、体积、制造与未验证项，不能靠不完整的一个分数掩盖硬约束。

07 / COMPILE ONE SOURCE

从可连接的数学网络编译到当前依赖图。

保持现有数学核

单位、表达式、公式注册、DAG、微分与优化器继续提供通用能力；不增加if family=P之类的领域特判。

外层挑配方、选择实例、提出变更；CAD/FE/报告读取同源投影，不再维护第二套几何或强度公式。

用户改一个齿数、模数、级序或元件后，先更新同一设计修订，受影响参数、系统载荷、轴承/轴/箱体、CAD/FE与批准证据按依赖标记失效，再重算/重建。库模板版本升级不静默改变旧设计；实例迁移必须留下差异。具体数值来自实例数学源，而不是从案例库覆盖回来。

公式复用与变量隔离：同一种公式只维护一份定义，每个实例用 instance_id + quantity_id 标识自己的变量。编译器生成无冲突的安全符号，再通过别名、方向和单位转换约束连接端口。H1的输出成为H2的输入后，该量不再允许第二份独立手工覆盖；重复驱动或冲突条件应拒绝。这是拟建编译器的验收要求，不能靠直接合并多个同名DAG实现。

上一轮“新转矩未进入固定模板优化”的反例应成为首个消费检验：新接口必须报告实际使用的载荷和约束。每一个必需需求字段要有consumer或明确blocked，不能仅出现在自然语言解释中。
